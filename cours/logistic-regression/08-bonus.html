Les bonus pour aller plus loin

La partie obligatoire est faite ? Parfait. Ces bonus ne sont pas juste des points en plus — ce sont les briques fondamentales que tu retrouveras dans Multilayer Perceptron et Total Perspective Vortex.

1. Early stopping + courbe de coût

Au lieu de fixer un nombre arbitraire d'itérations (10 000), on arrête l'entraînement quand le coût ne diminue plus significativement.

Le principe

À chaque itération, on calcule le coût $J$. Si la différence avec l'itération précédente est plus petite qu'un seuil $\epsilon$ (ex: $10^{-6}$), on s'arrête. 

for iteration in range(max_iterations):
    # ... gradient descent ...
    current_cost = cost(theta, X, y)
    costs.append(current_cost)

    if iteration > 0 and abs(costs[-2] - current_cost) < epsilon:
        print(f"Convergence atteinte à l'itération {iteration}")
        break

La courbe de coût

Après l'entraînement, tracer plt.plot(costs). Tu dois voir une courbe qui descend et se stabilise en plateau. Si elle oscille ou monte, ton learning rate est trop grand.

Pour Multilayer Perceptron

L'early stopping est indispensable en deep learning. Sans lui, un réseau de neurones continue à s'entraîner au-delà du point optimal et commence à overfitter — il mémorise les données au lieu de généraliser. Tu le réutiliseras tel quel.

2. Régularisation L2 (Ridge)

L'idée : pénaliser les poids qui deviennent trop grands. Des poids géants signifient que le modèle est trop sensible à certaines features → overfitting.

La formule modifiée

On ajoute un terme au coût :

$$J(\theta) = -\frac{1}{m} \sum \left[ y \log(h) + (1-y) \log(1-h) \right] + \frac{\lambda}{2m} \sum_{j=1}^{n} \theta_j^2$$

Le terme $\frac{\lambda}{2m} \sum \theta_j^2$ pénalise les gros poids. $\lambda$ (lambda) contrôle la force de la pénalité :

  • $\lambda = 0$ → pas de régularisation (comportement normal)
  • $\lambda$ petit (ex: 0.1) → légère régularisation
  • $\lambda$ grand (ex: 100) → poids forcés vers 0 → modèle trop simple (underfitting)
Attention

On ne régularise pas $\theta_0$ (le biais). Le biais ne correspond pas à une feature — le pénaliser n'a pas de sens. La somme va de $j = 1$ à $n$, pas de $j = 0$.

L'impact sur le gradient

Le gradient change légèrement :

$$\frac{\partial J}{\partial \theta_j} = \frac{1}{m} \sum (h - y) \cdot x_j + \frac{\lambda}{m} \theta_j \quad \text{(pour } j \geq 1\text{)}$$

En pratique, c'est 3 lignes de code en plus dans ta boucle de gradient : 

# Après le calcul normal du gradient :
for j in range(1, n + 1):  # skip j=0 (biais)
    gradients[j] += (lambda_reg / m) * theta[j]
Pour Multilayer Perceptron

La régularisation L2 est le mécanisme anti-overfitting le plus fondamental en deep learning. Le terme est exactement le même — tu ajouteras juste $\frac{\lambda}{2m} \sum w^2$ au coût de chaque couche.

3. Métriques + matrice de confusion

Au-delà de l'accuracy

L'accuracy seule peut être trompeuse. Si 90% des élèves sont Gryffindor, un modèle qui répond toujours « Gryffindor » a 90% d'accuracy mais ne sait rien. Les métriques par classe sont plus informatives :

  • Precision — parmi ceux que le modèle a classés « Gryffindor », combien le sont vraiment ? $$\text{precision} = \frac{TP}{TP + FP}$$
  • Recall — parmi les vrais Gryffindor, combien le modèle en a-t-il trouvés ? $$\text{recall} = \frac{TP}{TP + FN}$$
  • F1-score — la moyenne harmonique des deux : $$F_1 = 2 \cdot \frac{\text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}}$$

Où $TP$ = vrais positifs, $FP$ = faux positifs, $FN$ = faux négatifs.

La matrice de confusion

C'est un tableau $K \times K$ qui montre, pour chaque classe réelle, combien d'élèves ont été classés dans chaque classe prédite. Exemple :

Prédit GPrédit SPrédit RPrédit H
Vrai G98101
Vrai S09523
Vrai R10972
Vrai H02197

La diagonale = les prédictions correctes. Tout ce qui est hors diagonale = les erreurs. Tu peux la tracer avec plt.imshow() pour une version visuelle.

4. Mini-batch et Stochastic Gradient Descent

Le batch GD classique

Ce que tu as implémenté : à chaque itération, on parcourt tous les $m$ exemples pour calculer un gradient. C'est précis mais lent quand $m$ est grand.

Stochastic GD (SGD)

On met à jour les poids après chaque exemple (un seul !). Le gradient est très bruyant (basé sur un seul point), mais les mises à jour sont très fréquentes → convergence souvent plus rapide. 

for epoch in range(epochs):
    # Mélanger les données à chaque epoch
    shuffle(indices)
    for i in indices:
        h = sigmoid(dot(theta, X[i]))
        error = h - y[i]
        for j in range(n + 1):
            theta[j] -= alpha * error * X[i][j]

Mini-batch GD

Le compromis : on découpe les données en lots (batches) de taille $B$ (typiquement 32 ou 64). On calcule le gradient sur un lot, on met à jour, puis on passe au lot suivant. 

batch_size = 32
for epoch in range(epochs):
    shuffle(indices)
    for start in range(0, m, batch_size):
        batch = indices[start:start + batch_size]
        gradients = [0.0] * (n + 1)
        for i in batch:
            h = sigmoid(dot(theta, X[i]))
            error = h - y[i]
            for j in range(n + 1):
                gradients[j] += error * X[i][j]
        for j in range(n + 1):
            theta[j] -= alpha * gradients[j] / len(batch)
Pour Multilayer Perceptron

Tous les réseaux de neurones modernes utilisent le mini-batch GD. Le batch GD classique est trop lent dès qu'on a plus de quelques milliers d'exemples. Implémenter le mini-batch ici te prépare directement.

5. Softmax — la vraie multiclasse

Avec One-vs-All, les 4 probabilités sont indépendantes et ne somment pas à 1. La régression softmax résout ça : elle donne directement une distribution de probabilités sur les 4 classes.

La fonction Softmax

Au lieu de 4 sigmoïdes indépendantes, on calcule :

$$P(y = k \mid x) = \frac{e^{\theta_k^T x}}{\sum_{j=1}^{K} e^{\theta_j^T x}}$$

Les 4 probabilités somment à 1. C'est la généralisation naturelle de la sigmoïde à $K$ classes.

La fonction de coût : Categorical Cross-Entropy

$$J(\theta) = -\frac{1}{m} \sum_{i=1}^{m} \sum_{k=1}^{K} y_k^{(i)} \log(P(y = k \mid x^{(i)}))$$

Où $y_k^{(i)} = 1$ si l'élève $i$ est dans la classe $k$, 0 sinon (encodage one-hot).

Le gradient (bonne nouvelle)

Le gradient garde exactement la même forme :

$$\frac{\partial J}{\partial \theta_{k,j}} = \frac{1}{m} \sum_{i=1}^{m} (P(y = k \mid x^{(i)}) - y_k^{(i)}) \cdot x_j^{(i)}$$

C'est la même structure que le gradient de la logistique binaire — $(h - y) \cdot x$. La seule différence : on a $K$ vecteurs de poids au lieu de 4 classifieurs séparés, et $h$ est remplacé par le softmax.

Stabilité numérique du Softmax

$e^{z}$ peut exploser si $z$ est grand. Astuce : soustraire $\max(z_1, \ldots, z_K)$ de chaque $z_k$ avant de calculer les exponentielles. Le résultat est mathématiquement identique mais numériquement stable. 

def softmax(scores):
    # scores = [θ₁ᵀx, θ₂ᵀx, θ₃ᵀx, θ₄ᵀx]
    max_s = max(scores)
    exps = [math.exp(s - max_s) for s in scores]
    total = sum(exps)
    return [e / total for e in exps]
Pour Multilayer Perceptron

La couche de sortie d'un réseau de neurones multiclasse est exactement un softmax. Si tu l'implémentes ici, tu auras littéralement la dernière couche de ton réseau de neurones déjà prête. C'est aussi la couche la plus « magique » — elle transforme des scores bruts en une distribution de probabilités.
