Chapitre 5 · §1

Mettre les features à la même échelle

Tes features ont des échelles très différentes : Astronomy va de $-1000$ à $+1000$, Potions de $-19$ à $+21$. Si tu lances le gradient descent sans normaliser, certains poids vont bouger mille fois plus vite que d'autres. Le modèle va diverger ou converger très lentement.

1. Le problème des échelles

Le gradient pour $\theta_j$ est proportionnel à $x_j$ (la feature $j$). Si Astronomy vaut $800$ et Potions vaut $3$, le gradient de $\theta_{\text{Astro}}$ sera ~$267\times$ plus grand que celui de $\theta_{\text{Potions}}$. Avec le même learning rate $\alpha$, le poids d'Astronomy fait d'énormes bonds tandis que celui de Potions rampe.

Résultat : le gradient descent zigzague au lieu de descendre droit, ou pire, il diverge.

2. La standardisation (Z-score)

La solution la plus courante est la standardisation. Pour chaque feature $j$, on transforme les valeurs pour qu'elles aient une moyenne de 0 et un écart-type de 1 :

$$x_j' = \frac{x_j - \mu_j}{\sigma_j}$$

Où :

  • $\mu_j$ = la moyenne de la feature $j$ sur le dataset d'entraînement
  • $\sigma_j$ = l'écart-type de la feature $j$ sur le dataset d'entraînement

Après standardisation, toutes les features sont centrées autour de 0 et ont la même dispersion. Le gradient descent converge beaucoup plus vite.

Min-Max vs Z-score

L'alternative est la normalisation min-max : $x' = \frac{x - \min}{\max - \min}$, qui met tout entre 0 et 1. Les deux marchent. La standardisation est préférée en logistique parce qu'elle gère mieux les outliers et centre les données autour de 0 (ce qui aide la sigmoïde).

3. Exemple concret

ÉlèveAstronomy (brut)Astronomy (standardisé)
Harry$-487.0$$-0.73$
Draco$260.5$$0.88$
Luna$-22.3$$0.27$

Si $\mu = -150$ et $\sigma = 460$, alors pour Harry : $\frac{-487 - (-150)}{460} = \frac{-337}{460} = -0.73$.

Maintenant Astronomy et Potions sont sur la même échelle (autour de $[-2, +2]$ typiquement), et leurs gradients auront des magnitudes comparables.

4. Attention : sauvegarder $\mu$ et $\sigma$

C'est un point crucial. Tu calcules $\mu$ et $\sigma$ sur le dataset d'entraînement. Mais quand tu prédis sur le dataset de test, tu dois utiliser les mêmes $\mu$ et $\sigma$, pas ceux du test.

Les paramètres de normalisation ($\mu$, $\sigma$) font partie du modèle. Ils doivent être sauvegardés avec les poids $\theta$.

Sinon, les données du test seront à une échelle différente de celles de l'entraînement, et les poids $\theta$ (qui ont été appris sur des données standardisées) ne fonctionneront pas.

Dans ton code

logreg_train.py calcule $\mu$ et $\sigma$ pour chaque feature et les sauvegarde dans le fichier de poids (avec les $\theta$).
logreg_predict.py les recharge et les applique au dataset de test avant de prédire.

5. En Python

# Standardiser une liste de valeurs
def standardize(values):
    mu = mean(values)
    sigma = std(values)
    return [(v - mu) / sigma for v in values], mu, sigma

# Appliquer la standardisation avec des paramètres connus
def apply_standardize(values, mu, sigma):
    return [(v - mu) / sigma for v in values]
Piège classique

Si une feature a un écart-type de 0 (toutes les valeurs sont identiques), tu divises par 0. Solution : soit ignorer cette feature (elle n'apporte aucune information), soit remplacer $\sigma = 0$ par $\sigma = 1$ pour éviter la division par zéro.

6. Gérer les valeurs manquantes

Ton dataset contient des cases vides (NaN). Avant de normaliser, tu dois les gérer. Deux stratégies simples :

  • Imputation par la moyenne — remplacer les NaN par $\mu_j$ de la feature. Après standardisation, ces valeurs deviennent 0 (neutre). C'est simple et efficace.
  • Imputation par la médiane — plus robuste aux outliers. Mêmes avantages.

Pour le projet, l'imputation par la moyenne suffit largement pour atteindre 98%.

7. Résumé

  • Standardiser chaque feature : $x' = \frac{x - \mu}{\sigma}$
  • Calculer $\mu$ et $\sigma$ sur le train set uniquement
  • Sauvegarder $\mu$ et $\sigma$ avec les poids
  • Appliquer la même transformation au test set avec les mêmes paramètres
  • Remplacer les NaN par la moyenne avant de standardiser
