Chapitre 3 · §1

Mesurer l'erreur du classifieur

Le modèle sort une probabilité. Les données disent « oui » ou « non ». Il faut un nombre unique qui dit à quel point le modèle se trompe. C'est l'équation la plus longue du sujet — on va la décortiquer pièce par pièce.

1. L'équation du sujet

Voici la formule telle qu'elle apparaît dans l'annexe (page 11) :

$$J(\theta) = -\frac{1}{m} \sum_{i=1}^{m} y^i \log(h_\theta(x^i)) + (1 - y^i) \log(1 - h_\theta(x^i))$$

C'est intimidant. Mais on va voir que chaque morceau a un sens simple.

2. Chaque symbole expliqué

  • $J$ — c'est le nom de la fonction de coût. $J(\theta)$ = « le coût quand les poids sont $\theta$ ». Plus $J$ est petit, meilleur est le modèle.
  • $\theta$ — les poids du modèle (ceux qu'on essaie d'optimiser).
  • $m$ — le nombre d'exemples dans le dataset. Pour toi, $m = 1600$ (le nombre d'élèves dans dataset_train.csv).
  • $\sum_{i=1}^{m}$ — le symbole somme. Ça veut dire « additionne le calcul qui suit pour chaque élève $i$, de $i = 1$ jusqu'à $i = m$ ». C'est une boucle for en maths.
  • $i$ — l'indice de l'élève. L'élève numéro 1, numéro 2, …, numéro $m$.
  • $y^i$ — la vraie réponse pour l'élève $i$. C'est soit $1$ (« oui, c'est cette maison ») soit $0$ (« non »). Le $i$ en exposant est un indice, pas une puissance.
  • $x^i$ — les notes de l'élève $i$ (son vecteur de features).
  • $h_\theta(x^i)$ — la prédiction du modèle pour l'élève $i$. C'est la probabilité qu'on a calculée au chapitre 2 (sigmoïde du produit scalaire). Un nombre entre 0 et 1.
  • $\log$ — le logarithme naturel (base $e$). En Python : math.log(). Propriété clé : $\log$ d'un nombre entre 0 et 1 est toujours négatif.
  • $-\frac{1}{m}$ — le signe moins rend le coût positif (car les logs sont négatifs), et la division par $m$ fait la moyenne sur tous les élèves.

3. L'astuce des deux termes

La formule a deux morceaux additionnés. Regardons ce que chacun fait :

$$\underbrace{y^i \log(h_\theta(x^i))}_{\text{Terme A}} + \underbrace{(1 - y^i) \log(1 - h_\theta(x^i))}_{\text{Terme B}}$$

Quand $y^i = 1$ (l'élève EST dans la maison)

  • Terme A : $1 \times \log(h) = \log(h)$ → actif
  • Terme B : $(1 - 1) \times \log(1-h) = 0 \times \ldots = 0$ → s'annule

Il ne reste que $\log(h)$. On mesure : « à quel point le modèle a prédit près de 1 ? »

Quand $y^i = 0$ (l'élève N'EST PAS dans la maison)

  • Terme A : $0 \times \log(h) = 0$ → s'annule
  • Terme B : $(1 - 0) \times \log(1-h) = \log(1-h)$ → actif

Il ne reste que $\log(1-h)$. On mesure : « à quel point le modèle a prédit près de 0 ? »

C'est un interrupteur automatique. Comme $y$ vaut toujours 0 ou 1, un des deux termes s'éteint systématiquement. Pas besoin de if dans le code — la formule gère les deux cas toute seule.

4. Pourquoi le log ?

Le $\log$ pénalise les erreurs de manière asymétrique. Plus le modèle est sûr de lui et se trompe, plus la punition est sévère :

Cas $y = 1$ : le modèle devrait prédire haut

Prédiction $h$$\log(h)$Coût $-\log(h)$En mots
$0.99$$-0.01$$0.01$Prédit bien → quasi pas puni
$0.8$$-0.22$$0.22$Pas mal → petite punition
$0.5$$-0.69$$0.69$Hésite → punition moyenne
$0.2$$-1.61$$1.61$Se trompe → grosse punition
$0.01$$-4.61$$4.61$Certain d'avoir tort → punition énorme

Remarque : quand $h \to 0$ (le modèle est sûr que c'est « non ») alors que $y = 1$ (c'est « oui »), le coût $\to +\infty$.

Cas $y = 0$ : le modèle devrait prédire bas

Prédiction $h$$1 - h$$\log(1-h)$Coût $-\log(1-h)$
$0.01$$0.99$$-0.01$$0.01$ → quasi pas puni
$0.3$$0.7$$-0.36$$0.36$ → punition modérée
$0.9$$0.1$$-2.30$$2.30$ → grosse punition
$0.99$$0.01$$-4.61$$4.61$ → punition énorme
Pourquoi pas juste la différence ?

On pourrait se dire « je prends juste $|h - y|$ comme erreur ». Le problème : si le modèle prédit $h = 0.01$ au lieu de $y = 1$, l'erreur serait $0.99$. Mais si le modèle prédit $h = 0.4$ au lieu de $y = 1$, l'erreur serait $0.6$. La différence entre les deux punitions n'est que de $0.39$, alors que le premier cas est catastrophique et le deuxième juste « moyen ». Le $\log$ amplifie les erreurs graves : $-\log(0.01) = 4.61$ vs $-\log(0.4) = 0.92$ → un écart de $3.69$, beaucoup plus marqué.

5. Exemple complet, pas à pas

Prenons 3 élèves et le classifieur « est-ce un Gryffindor ? » :

ÉlèveVrai $y$Prédit $h$Terme actifCalculCoût
Harry$1$$0.9$$\log(h)$$-\log(0.9) = -(-0.105)$$0.105$
Draco$0$$0.2$$\log(1-h)$$-\log(0.8) = -(-0.223)$$0.223$
Neville$1$$0.6$$\log(h)$$-\log(0.6) = -(-0.511)$$0.511$

Le coût total :

$$J = -\frac{1}{3} \left[ \underbrace{1 \times \log(0.9) + 0 \times \log(0.8)}_{\text{Harry}} + \underbrace{0 \times \log(0.2) + 1 \times \log(0.8)}_{\text{Draco}} + \underbrace{1 \times \log(0.6) + 0 \times \log(0.4)}_{\text{Neville}} \right]$$ $$J = -\frac{1}{3} \left[ (-0.105) + (-0.223) + (-0.511) \right] = -\frac{-0.839}{3} = \frac{0.839}{3} = 0.280$$

Le coût est $0.280$. L'objectif du gradient descent : faire baisser ce nombre en ajustant les $\theta$.

6. La formule = une boucle for

En Python, la formule du sujet se traduit littéralement en : 

def cost(theta, X, y):
    m = len(y)                            # nombre d'élèves
    total = 0
    for i in range(m):                    # Σ de i=1 à m
        h = hypothesis(theta, X[i])       # h_θ(xⁱ)
        # Terme A           + Terme B
        total += y[i] * math.log(h) + (1 - y[i]) * math.log(1 - h)
    return -total / m                     # -1/m × la somme

Chaque ligne correspond à un morceau de la formule. La $\sum$ est la boucle for. Le $-\frac{1}{m}$ est le return.

Piège classique

$\log(0)$ vaut $-\infty$ et fera planter ton programme. Si $h = 0$ ou $h = 1$ exactement, le log explose. Solution : avant de calculer le log, clippe $h$ : 

h = max(1e-15, min(1 - 1e-15, h))

Ça empêche $h$ d'être exactement 0 ou 1.

7. Visualiser le coût pendant l'entraînement

À chaque itération du gradient descent, tu calcules $J$. Il doit diminuer régulièrement. Si tu le traces :

  • Courbe qui descend et se stabilise → tout va bien, le modèle converge
  • Courbe qui monte → learning rate trop grand, le modèle diverge
  • Courbe qui descend très lentement → learning rate trop petit
  • Courbe qui oscille → learning rate trop grand aussi
Dans ton code

Stocke $J$ dans une liste à chaque itération. Après l'entraînement, trace-la : plt.plot(costs). C'est ton outil de debug numéro 1, et c'est un bonus du sujet.

8. Résumé

  • La formule du sujet $J(\theta) = -\frac{1}{m} \sum \left[ y \log(h) + (1-y) \log(1-h) \right]$ mesure l'erreur moyenne
  • $y$ vaut 0 ou 1 → un seul des deux termes est actif à chaque fois
  • Le $\log$ punit exponentiellement les certitudes erronées
  • $-\frac{1}{m}$ donne la moyenne et rend le résultat positif
  • En code : une boucle for sur les élèves, qui additionne les coûts individuels
  • Un $J$ qui baisse = le modèle apprend. Un $J$ qui monte = problème de learning rate.
