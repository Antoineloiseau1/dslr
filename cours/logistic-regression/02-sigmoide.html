Chapitre 2 · §1

Transformer un score en probabilité

Le sujet donne deux formules liées. On va les décortiquer symbole par symbole, en commençant par la plus simple : la sigmoïde.

1. Équation du sujet : $g(z) = \frac{1}{1 + e^{-z}}$

C'est la première formule de l'annexe (page 11). On va la lire morceau par morceau.

Chaque symbole expliqué

  • $g$ — c'est juste le nom de la fonction. On l'appelle $g$ (ou parfois $\sigma$). C'est la sigmoïde.
  • $z$ — c'est l'entrée de la fonction. Un nombre quelconque : $-50$, $0$, $3.7$, $1000$… n'importe quoi.
  • $e$ — c'est le nombre d'Euler, une constante mathématique ≈ $2.71828$. C'est comme $\pi$, mais pour les exponentielles. En Python : math.exp().
  • $e^{-z}$ — c'est $e$ élevé à la puissance $-z$. Si $z = 2$, alors $e^{-z} = e^{-2} \approx 0.135$. Si $z = -3$, alors $e^{-z} = e^{3} \approx 20.09$.
  • $1 + e^{-z}$ — on ajoute 1 au résultat. C'est toujours un nombre $> 1$.
  • $\frac{1}{1 + e^{-z}}$ — on divise 1 par ce résultat. Comme le dénominateur est toujours $> 1$, le résultat est toujours $< 1$. Et comme $e^{-z}$ est toujours positif, le dénominateur est toujours $> 0$, donc le résultat est toujours $> 0$.
Conclusion : peu importe la valeur de $z$, la sortie de $g(z)$ est toujours entre 0 et 1. C'est ça qui en fait une probabilité.

Calculons à la main

Prenons $z = 2$ :

  1. $-z = -2$
  2. $e^{-2} = \frac{1}{e^2} \approx \frac{1}{7.389} \approx 0.135$
  3. $1 + 0.135 = 1.135$
  4. $\frac{1}{1.135} \approx 0.881$

Donc $g(2) \approx 0.88$. Le modèle est à 88% sûr que c'est « oui ».

Prenons $z = -3$ :

  1. $-z = 3$
  2. $e^{3} \approx 20.09$
  3. $1 + 20.09 = 21.09$
  4. $\frac{1}{21.09} \approx 0.047$

Donc $g(-3) \approx 0.05$. Le modèle est à 5% → « probablement non ».

Prenons $z = 0$ :

  1. $-z = 0$
  2. $e^{0} = 1$ (n'importe quoi élevé à la puissance 0 vaut 1)
  3. $1 + 1 = 2$
  4. $\frac{1}{2} = 0.5$

Donc $g(0) = 0.5$. Pile au milieu : le modèle hésite complètement.

Intuition

La sigmoïde est un traducteur. Elle prend un score brut (n'importe quel nombre réel) et le transforme en probabilité (entre 0 et 1). Un score très positif → « oui ». Un score très négatif → « non ». Un score autour de 0 → « je sais pas ».

2. Équation du sujet : $h_\theta(x) = g(\theta^T x)$

C'est la deuxième formule de l'annexe. Elle utilise la sigmoïde $g$ qu'on vient de voir. On va décomposer.

Chaque symbole expliqué

  • $h$ — c'est l'hypothèse, la fonction qui fait la prédiction. Elle prend un élève en entrée et sort une probabilité.
  • $\theta$ — (prononcé « thêta ») ce sont les poids du modèle. C'est ce que le modèle apprend. C'est une liste de nombres : $[\theta_0, \theta_1, \theta_2, \ldots, \theta_n]$.
  • $h_\theta$ — « l'hypothèse avec les poids $\theta$ ». Le petit $\theta$ en indice rappelle que la prédiction dépend des poids qu'on a choisis.
  • $x$ — c'est un élève, représenté par ses notes : $[x_1, x_2, \ldots, x_n]$. Par exemple, $x_1$ = sa note en Astronomy, $x_2$ = sa note en Herbology, etc.
  • $\theta^T$ — le $T$ veut dire transposé. En pratique, ça permet de faire le produit scalaire. Si tu connais pas la transposée, ignore le $T$ : retiens juste que $\theta^T x$ est le produit scalaire.
  • $\theta^T x$ — le produit scalaire entre $\theta$ et $x$. C'est une multiplication terme à terme, puis une somme.
  • $g(\theta^T x)$ — on passe le résultat du produit scalaire dans la sigmoïde.

Le produit scalaire : c'est quoi concrètement ?

Imaginons un modèle simple avec seulement 3 features. Le modèle a 4 poids (un biais + un par feature) :

$$\theta = [\theta_0, \theta_1, \theta_2, \theta_3] = [0.5,\; -0.3,\; 1.2,\; 0.8]$$

Et un élève avec ses notes (on ajoute un $1$ au début pour le biais) :

$$x = [1,\; x_1,\; x_2,\; x_3] = [1,\; 0.7,\; -1.5,\; 2.1]$$

Le produit scalaire $\theta^T x$ c'est :

$$\theta^T x = \theta_0 \times 1 + \theta_1 \times x_1 + \theta_2 \times x_2 + \theta_3 \times x_3$$ $$= 0.5 \times 1 + (-0.3) \times 0.7 + 1.2 \times (-1.5) + 0.8 \times 2.1$$ $$= 0.5 - 0.21 - 1.8 + 1.68 = 0.17$$

On obtient $z = 0.17$. Maintenant on passe dans la sigmoïde :

$$h_\theta(x) = g(0.17) = \frac{1}{1 + e^{-0.17}} = \frac{1}{1 + 0.844} = \frac{1}{1.844} \approx 0.542$$

Le modèle donne 54.2% de chances que cet élève soit dans la classe « oui ». C'est quasi 50/50, il hésite.

Le produit scalaire $\theta^T x$ c'est juste multiplier chaque poids par la note correspondante, puis tout additionner. C'est une somme pondérée.

Ce que chaque poids signifie

  • $\theta_0 = 0.5$ — le biais. C'est le score de base, avant même de regarder les notes. Un biais positif = le modèle est déjà un peu penché vers « oui ».
  • $\theta_1 = -0.3$ — poids de la feature 1 (ex: Astronomy). Négatif → une bonne note en Astronomy réduit la probabilité de cette maison.
  • $\theta_2 = 1.2$ — poids de la feature 2 (ex: Herbology). Positif et grand → une bonne note en Herbology augmente fortement la probabilité.
  • $\theta_3 = 0.8$ — poids de la feature 3 (ex: Divination). Positif → une bonne note pousse vers « oui ».

Au début, tous les poids sont à 0. Le modèle ne sait rien. Le gradient descent va les ajuster petit à petit pour que les prédictions collent aux données.

3. L'astuce de la colonne de 1

Tu as vu qu'on ajoute un $1$ au début de $x$. Pourquoi ? Pour que le biais $\theta_0$ soit inclus automatiquement dans le produit scalaire, sans cas spécial dans le code :

$$x = \begin{bmatrix} 1 \\ x_1 \\ x_2 \\ \vdots \\ x_n \end{bmatrix}, \quad \theta = \begin{bmatrix} \theta_0 \\ \theta_1 \\ \theta_2 \\ \vdots \\ \theta_n \end{bmatrix}$$ $$\theta^T x = \underbrace{\theta_0 \times 1}_{\text{biais}} + \underbrace{\theta_1 x_1 + \theta_2 x_2 + \ldots + \theta_n x_n}_{\text{somme pondérée des notes}}$$
Dans ton code

Concrètement : tu as 1600 élèves et 11 features (notes). Tu ajoutes un 1 au début de chaque ligne. Ta matrice passe de $(1600 \times 11)$ à $(1600 \times 12)$. Le vecteur $\theta$ aura donc 12 éléments : 1 biais + 11 poids.

4. En Python

La sigmoïde se code en une seule fonction : 

import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

Et le produit scalaire + sigmoïde (l'hypothèse) : 

def hypothesis(theta, x):
    # Produit scalaire : θ₀×1 + θ₁×x₁ + θ₂×x₂ + ...
    z = 0
    for j in range(len(theta)):
        z += theta[j] * x[j]
    # Passer dans la sigmoïde
    return sigmoid(z)

C'est tout. C'est ça, $h_\theta(x) = g(\theta^T x)$.

Piège classique

Quand $z$ est très négatif (ex: $z = -800$), math.exp(800) dépasse la capacité d'un float → overflow. Solution au chapitre 7 (pipeline) : une version numériquement stable de la sigmoïde.

5. Récapitulatif visuel

Voici le chemin complet d'une prédiction, étape par étape : 

Notes de l'élève :     x = [1, 0.7, -1.5, 2.1]
Poids du modèle :      θ = [0.5, -0.3, 1.2, 0.8]

Étape 1 — Produit scalaire (θᵀx) :
   0.5×1 + (-0.3)×0.7 + 1.2×(-1.5) + 0.8×2.1
   = 0.5 - 0.21 - 1.8 + 1.68
   = 0.17           ← c'est z, le "score brut"

Étape 2 — Sigmoïde g(z) :
   g(0.17) = 1 / (1 + e⁻⁰·¹⁷)
          = 1 / (1 + 0.844)
          = 1 / 1.844
          = 0.542       ← c'est la probabilité

Résultat : 54.2% de chances → le modèle hésite

6. Résumé

  • $g(z) = \frac{1}{1 + e^{-z}}$ prend n'importe quel nombre → sort un nombre entre 0 et 1
  • $\theta^T x = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \ldots$ = somme pondérée des notes
  • $h_\theta(x) = g(\theta^T x)$ = on passe cette somme dans la sigmoïde → probabilité
  • Les poids $\theta$ sont ce que le modèle apprend. Au début tout est à 0.

Maintenant qu'on sait calculer une probabilité, il faut un moyen de mesurer à quel point cette probabilité est fausse. C'est le rôle de la fonction de coût.
