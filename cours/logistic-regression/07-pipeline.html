Chapitre 7 · §1

De A à Z dans ton code

Tu connais maintenant tous les ingrédients. Ce chapitre les assemble en un pipeline complet — le squelette de tes deux programmes logreg_train.py et logreg_predict.py.

1. logreg_train.py — vue d'ensemble

Voici les étapes dans l'ordre :

  1. Charger le CSV → extraire les features numériques et les labels
  2. Sélectionner les features utiles (exclure Arithmancy, Care of Magical Creatures)
  3. Gérer les NaN → remplacer par la moyenne de la feature
  4. Standardiser chaque feature → sauvegarder $\mu$ et $\sigma$
  5. Ajouter la colonne de 1 (biais) au début de la matrice
  6. Pour chaque maison : transformer les labels en binaire → gradient descent → stocker $\theta$
  7. Sauvegarder tous les $\theta$ + les $\mu$/$\sigma$ dans un fichier

Piège classique — les NaN

Les NaN doivent être gérés avant la standardisation. Si tu calcules la moyenne ou l'écart-type sur des données avec des NaN, le résultat sera NaN et tout s'effondre. Remplace les NaN d'abord, puis standardise.

3. La boucle d'entraînement

houses = ["Gryffindor", "Slytherin", "Ravenclaw", "Hufflepuff"]
all_thetas = {}

for house in houses:
    # Labels binaires
    y = [1 if label == house else 0 for label in labels]

    # Initialiser les poids à 0
    theta = [0.0] * (n + 1)  # n features + 1 biais

    # Gradient descent
    for iteration in range(iterations):
        gradients = [0.0] * (n + 1)
        for i in range(m):
            h = sigmoid(dot(theta, X[i]))
            error = h - y[i]
            for j in range(n + 1):
                gradients[j] += error * X[i][j]
        for j in range(n + 1):
            gradients[j] /= m
            theta[j] -= alpha * gradients[j]

    all_thetas[house] = theta

4. La sigmoïde numériquement stable

Quand $z$ est très négatif, $e^{-z}$ explose. Voici la version robuste : 

def sigmoid(z):
    if z >= 0:
        return 1 / (1 + math.exp(-z))
    else:
        ez = math.exp(z)
        return ez / (1 + ez)

Quand $z \geq 0$, on utilise la formule classique. Quand $z < 0$, on utilise la forme équivalente $\frac{e^z}{1 + e^z}$ qui évite de calculer $e^{800}$.

5. Sauvegarder les poids

Tu dois sauvegarder dans un fichier :

  • Les noms des features utilisées
  • Les $\mu$ et $\sigma$ de chaque feature (pour la normalisation)
  • Les 4 vecteurs $\theta$ (un par maison)

Le format est libre — CSV, JSON, etc. Un CSV simple avec une ligne par maison fonctionne bien.

Dans ton code

Une approche simple : un fichier CSV où chaque ligne contient le nom de la maison suivi des poids $\theta_0, \theta_1, \ldots, \theta_n$. Et un deuxième fichier (ou des lignes supplémentaires) pour les $\mu$ et $\sigma$.

6. logreg_predict.py — vue d'ensemble

  1. Charger le dataset de test et le fichier de poids
  2. Extraire les mêmes features que l'entraînement
  3. Gérer les NaN → imputer par la moyenne du train (sauvegardée dans $\mu$)
  4. Standardiser avec les $\mu$ et $\sigma$ du train
  5. Ajouter la colonne de 1
  6. Pour chaque élève → calculer les 4 probabilités → prendre le max

7. Vérifier l'accuracy

Le sujet dit ≥ 98%. Pour vérifier, tu peux utiliser le fichier dataset_truth.csv (s'il est fourni) ou faire une validation croisée sur le train set. La méthode la plus simple : 

# Comparer avec les vraies réponses
correct = 0
for pred, true in zip(predictions, truth):
    if pred == true:
        correct += 1
accuracy = correct / len(truth)
print(f"Accuracy: {accuracy * 100:.2f}%")

8. Checklist avant de coder

  • sigmoid(z) — version numériquement stable
  • hypothesis(theta, x) — produit scalaire + sigmoïde
  • cost(theta, X, y) — binary cross-entropy
  • gradient_descent(X, y, alpha, iterations) — retourne theta
  • standardize(feature) — retourne valeurs normalisées + mu + sigma
  • Imputation des NaN avant standardisation
  • Colonne de 1 ajoutée à X
  • Boucle One-vs-All : 4 entraînements
  • Sauvegarde des poids + mu/sigma
  • Prédiction : argmax des 4 probabilités
  • Écriture de houses.csv au bon format

9. Résumé

Tout le projet tient dans cette séquence : charger → nettoyer → normaliser → entraîner 4× → sauvegarder → recharger → prédire → écrire. Chaque étape est simple individuellement ; c'est l'assemblage qui fait le programme.
