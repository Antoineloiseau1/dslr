Chapitre 6 · §1

De binaire à multiclasse

On sait entraîner un classifieur qui répond oui ou non. Mais le Choixpeau doit choisir parmi 4 maisons. La stratégie One-vs-All transforme un problème à $K$ classes en $K$ problèmes binaires.

1. Le principe

Pour $K = 4$ classes (Gryffindor, Slytherin, Ravenclaw, Hufflepuff), on entraîne 4 classifieurs binaires indépendants :

Classifieur$y = 1$$y = 0$
$h_\theta^{(1)}$GryffindorTout le reste
$h_\theta^{(2)}$SlytherinTout le reste
$h_\theta^{(3)}$RavenclawTout le reste
$h_\theta^{(4)}$HufflepuffTout le reste

Chaque classifieur a ses propres poids $\theta^{(k)}$. Il apprend à répondre « est-ce la classe $k$ ? ».

2. L'entraînement

Pour entraîner le classifieur de Gryffindor, on transforme les labels :

  • Si l'élève est Gryffindor → $y = 1$
  • Sinon (Slytherin, Ravenclaw ou Hufflepuff) → $y = 0$

Puis on lance le gradient descent avec la binary cross-entropy, exactement comme dans les chapitres précédents. On obtient un vecteur de poids $\theta^{(\text{Gryff})}$.

On recommence pour Slytherin, Ravenclaw, Hufflepuff. À la fin, on a 4 vecteurs de poids.

One-vs-All = entraîner le même algorithme 4 fois, en changeant juste la définition de « oui » et « non ».
Pourquoi ça marche

Chaque classifieur apprend un « profil » différent. Le classifieur Gryffindor apprend que les Gryffindor ont plutôt telles et telles notes. Le classifieur Slytherin apprend un profil différent. Quand on présente un nouvel élève, le classifieur dont le profil correspond le mieux donne la probabilité la plus haute.

3. La prédiction

Pour prédire la maison d'un nouvel élève $x$ :

  1. Calculer $h_\theta^{(1)}(x)$ = probabilité d'être Gryffindor
  2. Calculer $h_\theta^{(2)}(x)$ = probabilité d'être Slytherin
  3. Calculer $h_\theta^{(3)}(x)$ = probabilité d'être Ravenclaw
  4. Calculer $h_\theta^{(4)}(x)$ = probabilité d'être Hufflepuff
  5. Prendre la classe avec la probabilité maximale
$$\text{prédiction} = \arg\max_{k} \; h_\theta^{(k)}(x)$$

Exemple

ClassifieurProbabilité
Gryffindor$0.12$
Slytherin$0.05$
Ravenclaw$\mathbf{0.71}$
Hufflepuff$0.32$

→ Ravenclaw a la probabilité la plus haute (0.71). Le modèle prédit Ravenclaw.

Les probabilités ne s'additionnent pas à 1

Tu auras remarqué : $0.12 + 0.05 + 0.71 + 0.32 = 1.20$, pas $1.0$. C'est normal. Chaque classifieur est indépendant — il donne sa propre probabilité sans se soucier des autres. Si tu veux que ça somme à 1, c'est le bonus Softmax qui le fait (voir chapitre bonus).

4. En pseudo-code

# Entraînement
houses = ["Gryffindor", "Slytherin", "Ravenclaw", "Hufflepuff"]
all_thetas = {}

for house in houses:
    # Transformer les labels : 1 si cette maison, 0 sinon
    y_binary = [1 if label == house else 0 for label in labels]
    # Entraîner avec gradient descent
    theta = gradient_descent(X, y_binary, alpha, iterations)
    all_thetas[house] = theta
# Prédiction
def predict(x, all_thetas):
    best_house = None
    best_prob = -1
    for house, theta in all_thetas.items():
        prob = sigmoid(dot(theta, x))
        if prob > best_prob:
            best_prob = prob
            best_house = house
    return best_house
Dans ton code

logreg_train.py boucle sur les 4 maisons, entraîne un classifieur par maison, et sauvegarde les 4 vecteurs $\theta$ (+ les $\mu$/$\sigma$ de normalisation) dans un fichier CSV.
logreg_predict.py charge ce fichier, calcule les 4 probabilités pour chaque élève, et écrit la maison la plus probable dans houses.csv.

5. Format de sortie

Le sujet exige que houses.csv ait exactement ce format : 

Index,Hogwarts House
0,Gryffindor
1,Hufflepuff
2,Ravenclaw
3,Hufflepuff
4,Slytherin
...

6. Résumé

  • One-vs-All : pour $K$ classes, entraîner $K$ classifieurs binaires
  • Chaque classifieur répond « est-ce la classe $k$ ? oui/non »
  • Pour prédire : lancer les $K$ classifieurs, prendre celui qui a la probabilité max
  • Les probabilités ne somment pas à 1 (contrairement à Softmax)
  • En pratique, tu boucles sur les 4 maisons et tu fais exactement le même entraînement 4 fois
