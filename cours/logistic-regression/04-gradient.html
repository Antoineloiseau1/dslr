Chapitre 4 · §1

Apprendre par descente de gradient

On a un coût $J(\theta)$ qui mesure l'erreur. On veut le minimiser. La dernière formule du sujet nous dit dans quelle direction ajuster chaque poids.

1. Rappel : le gradient descent en 3 phrases

Tu l'as déjà fait en ft_linear_regression. Le principe :

  1. On calcule la pente (le gradient) du coût par rapport à chaque poids $\theta_j$
  2. On fait un petit pas dans la direction opposée à la pente (pour descendre)
  3. On recommence jusqu'à ce que le coût ne bouge plus

La règle de mise à jour pour chaque poids :

$$\theta_j := \theta_j - \alpha \times \frac{\partial J}{\partial \theta_j}$$

Où $\alpha$ est le learning rate (taille du pas). Et $\frac{\partial J}{\partial \theta_j}$ est la pente — c'est ça que la formule du sujet nous donne.

2. L'équation du sujet

Voici la dernière formule de l'annexe (page 11) :

$$\frac{\partial}{\partial \theta_j} J(\theta) = \frac{1}{m} \sum_{i=1}^{m} (h_\theta(x^i) - y^i) x_j^i$$

Chaque symbole expliqué

  • $\frac{\partial}{\partial \theta_j} J(\theta)$ — c'est la dérivée partielle du coût par rapport au poids $\theta_j$. En français : « de combien le coût change si je bouge un tout petit peu le poids $\theta_j$ ? ». C'est la pente.
  • $j$ — l'indice du poids qu'on est en train de calculer. $j = 0$ pour le biais, $j = 1$ pour le poids d'Astronomy, $j = 2$ pour Herbology, etc.
  • $\frac{1}{m}$ — on divise par le nombre d'élèves → c'est une moyenne.
  • $\sum_{i=1}^{m}$ — on additionne pour chaque élève $i$. C'est une boucle for i in range(m).
  • $h_\theta(x^i)$ — la prédiction du modèle pour l'élève $i$ (probabilité entre 0 et 1, calculée au ch.2).
  • $y^i$ — la vraie réponse pour l'élève $i$ ($0$ ou $1$).
  • $(h_\theta(x^i) - y^i)$ — l'erreur : la différence entre ce que le modèle a prédit et la réalité.
  • $x_j^i$ — la valeur de la feature $j$ pour l'élève $i$. Par exemple, si $j = 2$ (Herbology) et $i = 47$, c'est la note en Herbology de l'élève 47.

3. En français, ça dit quoi ?

La formule dit :

Pour savoir comment ajuster le poids $\theta_j$, regarde chaque élève : calcule l'erreur (prédiction − réalité), multiplie par la note $x_j$ de cet élève, et fais la moyenne de tout ça.

Pourquoi multiplier l'erreur par $x_j$ ? Parce que :

  • Si l'erreur est grande ET que la feature est grande → le poids doit beaucoup bouger
  • Si l'erreur est grande MAIS la feature est petite → le poids ne bouge pas tant (ce n'est pas « la faute » de cette feature)
  • Si l'erreur est quasi nulle → le poids ne bouge presque pas (pas besoin de corriger)

4. Exemple complet, pas à pas

Prenons un modèle simplifié avec seulement 2 features. On a 3 élèves. Les poids actuels sont $\theta = [0.1,\; 0.5,\; -0.3]$ (biais + 2 poids).

Élève $i$$x^i$ (avec le 1)$y^i$$h_\theta(x^i)$Erreur $(h - y)$
1$[1, \; 0.7, \; -1.5]$$1$$0.41$$0.41 - 1 = -0.59$
2$[1, \; -0.3, \; 2.1]$$0$$0.39$$0.39 - 0 = 0.39$
3$[1, \; 1.2, \; 0.5]$$1$$0.65$$0.65 - 1 = -0.35$

Calculons le gradient pour $\theta_0$ (le biais, $j = 0$)

On a $x_0^i = 1$ pour tout le monde (c'est la colonne de 1) :

$$\frac{\partial J}{\partial \theta_0} = \frac{1}{3} \left[ (-0.59) \times 1 + (0.39) \times 1 + (-0.35) \times 1 \right]$$ $$= \frac{1}{3} \left[ -0.59 + 0.39 - 0.35 \right] = \frac{-0.55}{3} = -0.183$$

Calculons le gradient pour $\theta_1$ (feature 1, $j = 1$)

On utilise $x_1^i$ (la note de la feature 1 de chaque élève) :

$$\frac{\partial J}{\partial \theta_1} = \frac{1}{3} \left[ (-0.59) \times 0.7 + (0.39) \times (-0.3) + (-0.35) \times 1.2 \right]$$ $$= \frac{1}{3} \left[ -0.413 - 0.117 - 0.42 \right] = \frac{-0.95}{3} = -0.317$$

Calculons le gradient pour $\theta_2$ (feature 2, $j = 2$)

$$\frac{\partial J}{\partial \theta_2} = \frac{1}{3} \left[ (-0.59) \times (-1.5) + (0.39) \times 2.1 + (-0.35) \times 0.5 \right]$$ $$= \frac{1}{3} \left[ 0.885 + 0.819 - 0.175 \right] = \frac{1.529}{3} = 0.510$$

Mise à jour des poids (avec $\alpha = 0.1$)

$$\theta_0 := 0.1 - 0.1 \times (-0.183) = 0.1 + 0.018 = 0.118$$ $$\theta_1 := 0.5 - 0.1 \times (-0.317) = 0.5 + 0.032 = 0.532$$ $$\theta_2 := -0.3 - 0.1 \times 0.510 = -0.3 - 0.051 = -0.351$$

Les poids ont légèrement bougé. $\theta_0$ et $\theta_1$ ont augmenté (gradient négatif → on ajoute), $\theta_2$ a diminué (gradient positif → on soustrait). C'est une itération. On recommence des milliers de fois.

Lecture de la mise à jour

Le gradient est négatif pour $\theta_0$ et $\theta_1$. Ça veut dire que le coût diminue si ces poids augmentent. Donc on les augmente. Le gradient est positif pour $\theta_2$. Ça veut dire que le coût diminue si ce poids diminue. Donc on le diminue. On va toujours dans la direction qui fait baisser le coût.

5. La formule = deux boucles for imbriquées

En code, une itération complète :

# alpha = learning rate (ex: 0.1)
# m = nombre d'élèves
# n+1 = nombre de poids (biais + features)

# Étape 1 : calculer TOUS les gradients
gradients = [0.0] * (n + 1)

for i in range(m):               # pour chaque élève
    h = hypothesis(theta, X[i])  # prédiction (sigmoïde)
    error = h - y[i]             # erreur = h - y

    for j in range(n + 1):       # pour chaque poids
        gradients[j] += error * X[i][j]  # erreur × feature

for j in range(n + 1):
    gradients[j] /= m            # diviser par m (moyenne)

# Étape 2 : mettre à jour TOUS les poids
for j in range(n + 1):
    theta[j] -= alpha * gradients[j]  # θⱼ := θⱼ - α × gradient
Piège classique — mise à jour simultanée

Il faut calculer tous les gradients d'abord, puis mettre à jour tous les poids en une fois. Si tu mets à jour $\theta_0$ avant de calculer le gradient de $\theta_1$, le gradient de $\theta_1$ utilisera le nouveau $\theta_0$ au lieu de l'ancien → calcul faussé. C'est pour ça qu'on a deux étapes séparées.

6. La boucle d'entraînement complète

# On répète l'opération des milliers de fois
for iteration in range(iterations):

    # ── Calcul des gradients ──
    gradients = [0.0] * (n + 1)
    for i in range(m):
        h = hypothesis(theta, X[i])
        error = h - y[i]
        for j in range(n + 1):
            gradients[j] += error * X[i][j]
    for j in range(n + 1):
        gradients[j] /= m

    # ── Mise à jour des poids ──
    for j in range(n + 1):
        theta[j] -= alpha * gradients[j]

C'est tout. C'est la boucle d'entraînement. Chaque tour de boucle est une itération du gradient descent. Le modèle s'améliore un peu à chaque tour.

7. Les hyperparamètres

NomSymboleRôleValeur pour commencer
Learning rate$\alpha$Taille du pas$0.1$ (baisser si ça diverge)
Itérations—Nombre de tours$10\,000$ (ou early stopping)
  • $\alpha$ trop grand → le coût explose (divergence)
  • $\alpha$ trop petit → le coût descend très lentement (10× plus d'itérations)
  • La courbe de coût (ch.3) est ton meilleur outil pour régler $\alpha$

8. La surprise : même formule que ft_linear_regression

Compare les deux :

Régression linéaireRégression logistique
Gradient$\frac{1}{m} \sum (h - y) \cdot x_j$$\frac{1}{m} \sum (h - y) \cdot x_j$
Hypothèse $h$$\theta^T x$ (linéaire)$g(\theta^T x)$ (sigmoïde)

La formule du gradient est identique. La seule différence est dans la façon dont on calcule $h$ : linéaire vs sigmoïde. Tout le reste — la boucle, la mise à jour, le learning rate — est pareil.

Tu sais déjà faire du gradient descent. Ici, il suffit de remplacer $h = \theta^T x$ par $h = g(\theta^T x)$. Le reste ne change pas.

9. Résumé

  • La formule du sujet $\frac{\partial J}{\partial \theta_j} = \frac{1}{m} \sum (h - y) \cdot x_j$ dit comment ajuster chaque poids
  • $(h - y)$ = l'erreur, $x_j$ = la feature correspondante
  • On calcule tous les gradients d'abord, puis on met à jour tous les poids
  • $\theta_j := \theta_j - \alpha \times \text{gradient}_j$
  • On répète des milliers de fois → le coût baisse → le modèle apprend
  • C'est la même formule qu'en régression linéaire — seul le $h$ change
